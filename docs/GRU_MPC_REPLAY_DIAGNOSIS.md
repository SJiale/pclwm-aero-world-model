## 三、任务 5：B2 时序分析（决定性证据）

### 3.1 关键事件时刻

| 事件 | 值 | 时刻 |
|---|---|---|
| **PLA 峰值** | **71.37°** | k=17, **t=1.68s** |
| N2 峰值 | 5243.4 rpm | k=25, **t=2.52s** |
| N2 首次越过目标 | 5099.9 rpm | k=20, t=2.00s |
| **PLA 峰值 → N2 峰值延迟** | — | **+0.84 s** |

### 3.2 ★★★ 决定性数据

**PLA 峰值 71.37° 对应多少稳态 N2？**

用可行性扫描插值：

```
PLA = 71.37°  →  稳态 N2 ≈ 5672.4 rpm
目标 N2      =  5099.3 rpm
超出         =  +573.1 rpm
```

**正确的 PLA（对应 5099）应该是 63.64°。**

**MPC 用了 71.37°，比正确值高 12.2%。**

### 3.3 时序解读

```
t=0.00s  PLA=55.70  N2=4349.6   err=-749.7
t=0.94s  PLA=64.08  N2=4540.5   err=-558.8   ← PLA 已超过正确值
t=1.57s  PLA=70.77  N2=4845.5   err=-253.8   ← PLA 继续升
t=1.68s  PLA=71.37  N2=~4900    峰值         ← PLA 峰值
t=1.89s  PLA=69.08  N2=5037.9   err=-61.4    ← PLA 已在回落
t=2.00s  PLA=—      N2=5099.9   首次达标     ← N2 才追上
t=2.52s  PLA=61.10  N2=5243.4   err=+144.1   ← N2 峰值（超调）
```

**关键观察**：
- **t=0.94s 时 PLA 已到 64.08（超过正确值 63.64），此时 N2 还差 559 rpm**
- **t=1.68s 时 PLA 达到 71.37（远超需求），此时 N2 还差约 200 rpm**
- **PLA 峰值比 N2 峰值早 0.84 s**

### 3.4 为什么这排除了"GRU 低估"

**如果 GRU 低估 N2，MPC 会认为"还差很多"→ 继续加油门。**

**但实测：GRU 在 32 步内能预测到 95% 的稳态值。**

**具体验证**：当 MPC 在 t≈1.68s 把 PLA 设为 71.37 时，GRU 预测的未来 3.36s：
- 从 4900 rpm → **约 5672×0.95 ≈ 5388 rpm**
- 而目标是 5099 rpm
- **GRU 明确告诉 MPC："你会冲到 5388，超过目标 289 rpm"**

**MPC 仍然选择了 71.37°，说明是优化器没有正确处理这个预测。**

## 四、任务 3：MPC 是否正确利用预测

### 4.1 无法直接验证（数据缺失）

**历史 MPC 日志未保存**：
- ❌ 每次优化的候选轨迹
- ❌ 最优预测轨迹
- ❌ 代价值

**因此无法从现有日志确定 MPC 当时是否"看到"了超调。**

### 4.2 但可以用代码逻辑推断

**查看 `mpc_opt.m` 的代价函数**：

```matlab
wv = ones(1,H);
wv(1:CFG.n_short) = CFG.w_short;      % 前 8 步权重 ×3
wv = wv / sum(wv);                     % ★ 归一化后总和=1

j_track = sum(wv .* (n2p - n2_ref).^2, 2);
j_du    = sum(diff([pla_prev, cand],1,2).^2, 2)
J = w_n2*j_track + w_du*j_du
```

**⚙️ 发现一个数值设计问题**：

`wv` 归一化后 `sum(wv)=1`，所以 `j_track` 是**加权平均平方误差**（量级 ~10⁴）。

而 `j_du = sum(ΔPLA²)` 是**求和**（H=32 项，量级 ~10²）。

**`w_du=1.0` 时：**
- `w_n2*j_track` ≈ 1.0 × (28 rpm)² ≈ **784**（若预测误差 28 rpm）
- `w_du*j_du` ≈ 1.0 × 32 × (1°)² ≈ **32**

**动作惩罚相对跟踪误差小 24 倍**，几乎不起作用。

**但这不是超调的直接原因**（超调是"动作太大"而非"动作不平滑"）。

### 4.3 真正可能的原因

**假设 B 的具体机制**：

MPC 每步只执行 PLA[0]，但由于：
1. **horizon 内 GRU 预测的是"PLA 保持常值"的响应**
2. 实际执行时 PLA 会继续变化
3. **每步重新优化，看到 N2 还没到目标，就继续加油门**
4. **等 N2 到了（有 0.84s 延迟），PLA 已经过冲**

**这是一个"模型预测 vs 执行延迟"的时序问题**，不是 GRU 精度问题。

**验证**：看 B2 的 PLA 序列，t=0.94s 到 t=1.68s 期间 PLA 从 64.08 升到 71.37，而 N2 从 4540 升到约 4900。

**MPC 在这 0.74s 内看到 N2 还差 200-560 rpm，所以继续加。**

**但它没考虑：PLA 已经 64+ 时，稳态 N2 已经是 5100+，只是还没到位。**

## 六、诊断结论

### 归因：**B（主）+ D（次）**

| 假设 | 判断 | 证据 |
|---|---|---|
| **A. GRU 低估未来转速** | ❌ **排除** | 稳态增益误差仅 0.5–1.9%；32 步内达稳态 93–97% |
| **B. GRU 已能预测超调，但 MPC 仍选不合理动作** | ✅ **最可能** | PLA 峰值 71.37° 对应稳态 5672 rpm（超目标 573），GRU 能预测到 |
| **C. 一步好但 3.36s 递推失准** | ❌ **排除** | 32 步 MAE 仅 27.77 rpm，且增益准确 |
| **D. 数据不足以完全区分** | ⚠️ **部分成立** | 无 MPC 内部日志（候选轨迹/代价），无法直接证明"MPC 看到了超调" |

### 最完整的解释

> **GRU 的预测能力是足够的**（稳态增益误差 <2%，3.36s 内达稳态 95%）。
>
> **超调来自 MPC 优化器与系统响应延迟的时序错配**：
> - EEC+发动机对 PLA 的响应有 **0.84s 延迟**
> - MPC 每 0.105s 重新优化，看到 N2 未达标就继续加大 PLA
> - **PLA 在 t=1.68s 冲到 71.37°，但此时 N2 只到约 4900**
> - 等 N2 响应到位（t=2.52s），PLA 的"过度加油"已经造成 +144 rpm 超调

### 数据局限（必须说明）

**无法从现有日志判定 MPC 当时是否"预见"了超调**，因为：
- 候选轨迹未保存
- 最优预测轨迹未保存
- 每步代价值未保存

**因此"B"是**基于 PLA-稳态映射的强推断**，不是直接证据。**

## 七、下一步：只推荐一项

### ✅ 推荐：保存 MPC 内部诊断数据，重跑一次短闭环

**具体做法**（单次约 2.5 分钟，12 步）：

在每个控制步记录：
1. **CEM 的最优预测轨迹**（`mu` 对应的 32 步 N2 预测）
2. **代价值分解**（`j_track`, `j_du`, `w_n2`, `w_du`）
3. **候选分布**（min/median/max 的 J）
4. 实际执行后的真实 N2

**为什么这是最值得做的**：

| 理由 | 说明 |
|---|---|
| **直接验证 B** | 若最优预测轨迹已显示"会到 5388"，则 B 确证 |
| **成本最低** | 12 步 × 11s ≈ 2.2 分钟 |
| **不改任何东西** | 只加日志，不动 GRU/CEM/权重 |
| **可复用** | 这个日志格式后续 RSSM/PC-LWM 对照也要用 |

**如果最优预测轨迹显示"只到 5100"，则归因改为 A/C（模型问题），需要重新审视。**

### 不推荐做的

- ❌ 继续跑长闭环（数据已有，问题已定位）
- ❌ 调 CEM 参数（还没确证是优化器问题）
- ❌ 训练新模型（先确认根因）
