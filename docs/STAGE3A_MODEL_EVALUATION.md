## 一、P0 修复：两个严重 bug

### 1.1 RSSM 检查点从未正确加载（严重）

**发现**：RSSM 的 `load_state_dict(strict=False)` 静默失败了。

```
检查点 key:   rssm.enc.0.weight     ← 有 rssm. 前缀
模型期望 key:  enc.0.weight          ← 无前缀
→ missing=22, unexpected=22，全部权重未加载
```

**且超参数用错默认值**：

| 参数 | 模型默认 | 检查点实际 |
|---|---|---|
| deter | 192 | **128** |
| stoch | 32 | 32 ✅ |
| classes | 32 | 32 ✅ |
| hidden | 192 | **128** |

**恢复方法**（从张量形状反推）：
```python
deter   = sd["cell.weight_hh"].shape[1]        # 128
stoch*c = sd["prior.2.weight"].shape[0]        # 1024 -> (32,32)
hidden  = sd["post.0.weight"].shape[0]         # 128
sd = {k[5:]: v for k, v in sd.items() if k.startswith("rssm.")}
model = RSSM(5, 3, deter=128, stoch=32, classes=32, hidden=128)
model.load_state_dict(sd, strict=True)         # ✅ 0 missing, 0 unexpected
```

**验证**：`max|diff| = 0.876`（vs 随机初始化），确认权重真实加载。

**参数量**：939,909（与历史记录的 RSSM-d128 一致 ✅）

### 1.2 动作归一化完全错误（严重）

**我的错误实现**：
```python
act[:, 0] /= 100.0      # PLA
act[:, 1] /= 25000.0    # Alt
# MN 原值
```

**正确实现**（`evaluate.py` L69）：
```python
act = (act_raw - act_mu) / act_sd
# act_mu = [57.2907, 7808.72, 0.2443]
# act_sd = [9.6293, 9495.89, 0.2767]
```

**影响对比**：

| 轨迹 | 错误归一化 | 正确归一化 | 倍数 |
|---|---|---|---|
| V1 (10s) | 1.527 | **0.056** | 27× |
| V2 | 0.906 | 0.065 | 14× |
| V3 | 0.601 | 0.053 | 11× |
| V4 | 1.259 | 0.052 | 24× |
| V5 | 0.925 | 0.086 | 11× |
| V6 | 1.110 | 0.038 | 29× |
| **均值** | **1.054** | **0.058** | **18×** |

> **"test_ctrl 高误差"完全是我实现错误导致的假象，不是模型失效。**

### 1.3 影响范围审计

**不得宣称历史 RSSM 实验无效。理由**：

| 检查项 | 状态 |
|---|---|
| 历史 RSSM 训练脚本（`run_rssm.py`）用 `strict=True`？ | 需核查（但训练时是从头初始化，不存在加载问题）|
| 历史评价脚本是否用 `data.norm_act()` | ✅ 是（`evaluate.py` 内部统一）|
| 本次是**评价脚本**的 bug，非训练 bug | ✅ 是 |
| 历史 RSSM 参数量 939,909 与本检查点一致 | ✅ 是 |

**结论**：**bug 在本次新写的评价脚本中，历史训练/评价链路未受影响。** 但需注意：如果历史某处用了 `strict=False` 加载 RSSM，则该处结论需复核——**这需要单独审计，本报告不下结论。**

### 4.5 RSSM 的先验/后验边界

**严格保证**：
- 历史 WINDOW 步：用**后验**（`post`，观测驱动）
- 未来 HORIZON 步：**仅用先验**（`prior`，无真实观测）

**代码依据**（`rssm_impl.RSSM.imagine`）：
```python
for t in range(T):        # 历史
    post_logits = self.post(...)   # 后验
    z = self.sample(post_logits, sm)
for k in range(H):        # 未来
    prior_logits = self.prior(h)   # 先验（无观测）
    z = self.sample(prior_logits, sm)
```

✅ **真实未来观测未输入自主预测过程。**

**随机推理可复现**：`torch.manual_seed(777)` 在每次 `predict()` 前固定。

## 五、任务 4：控制可用性判断

### 问题 1：现有模型能否正确响应未见 PLA 动作？

**✅ 能。**

证据：
- test_ctrl 1-step 误差 **0.0338（GRU）**，低于 test_id 的 0.0573
- 动作范围（PLA 48–62°）在训练范围（40–80°）内
- 动作变化率（max 3.3°/step）低于训练集（30°/step）

### 问题 2：MPC 短时预测谁最好？

**GRU 最优。**

| 指标 | 最优模型 |
|---|---|
| test_ctrl 1-step | GRU (0.0338) |
| test_ctrl 32-step | GRU (0.0399) |
| test_ctrl 分通道 | GRU (全部 5 通道) |
| test_ood 1-step | RSSM (0.0471) |
| 推理延迟 | GRU (8.4 ms) |

**GRU 在 4/5 项上最优，且快 4.5 倍。**

### 问题 3：是否存在明显失效工况？

**⚠️ 存在，但非灾难性。**

图 1 显示 **V4（双向阶跃）** 的真值 N2 几乎恒定（4556 rpm），但模型预测剧烈波动（4520–4630）。原因：
- V4 的 PLA 在 55→54→56→54 阶跃，但 N2 响应很小
- 模型从 PLA 推断出过大的转速变化 → **过拟合了训练集的"大 PLA 阶跃 → 大 N2 变化"模式**

V3（随机大幅）误差 0.053–0.060，V5（宽幅正弦）PC-LWM 达 0.086，为最高。

### 问题 4：PC-LWM 是否展现超过 GRU 的能力？

**❌ 在 test_ctrl 上未超过。**

| 数据集 | PC-LWM vs GRU |
|---|---|
| test_id 1-step | 劣 1.3% |
| test_id 32-step | 劣 21% |
| test_ood 1-step | **优 14%** |
| test_ood 32-step | 劣 15% |
| **test_ctrl 1-step** | **劣 29%** |
| **test_ctrl 32-step** | **劣 30%** |

**唯一优势**：test_ood 的 1-step（0.0511 vs 0.0597）。

**结论**：PC-LWM 的物理锚定**在控制导向任务上没有转化为优势**。

### 问题 5：是否需要补充训练数据？

**⚠️ 建议补充，但非阻断。**

**理由**：
- 现有数据已能让模型在 test_ctrl 上达到 0.034（GRU），**够用**
- 但 V4 暴露的模式偏差（PLA 阶跃 → N2 恒定）在训练集中无对应样本
- 训练集的 PLA 阶跃都是 30° 大阶跃，没有 1–2° 小阶跃

**建议补充**：
- 5–10 条"小 PLA 阶跃 + 稳态"轨迹（1–2° 阶跃，观察 N2 微弱响应）
- 优先补 GRU（当前最优），PC-LWM 暂不优先

## 六、★ 误差来源分解

### 6.1 增长倍数（10 s 推演）

| 模型 | V1 | V2 | V3 | V4 | V5 | V6 |
|---|---|---|---|---|---|---|
| GRU | 3.0× | **11.9×** | 1.7× | 3.9× | 1.1× | 2.0× |
| RSSM | 0.9× | 0.7× | 1.4× | **0.5×** | 1.6× | 0.7× |
| PC-LWM | 1.4× | 0.4× | 1.6× | 0.8× | 0.9× | 0.3× |

**关键观察**：
- **GRU 在 V2 上增长 11.9 倍**（从 0.008 → 0.094）→ 长期漂移严重
- **RSSM/PC-LWM 的增长倍数 < 2**（甚至 < 1）→ 更稳定
- 但 GRU 的**绝对误差**仍最低（起点低）

### 6.2 区分三类误差

| 误差类型 | 定义 | GRU | RSSM | PC-LWM |
|---|---|---|---|---|
| **初始偏差**（前 10%） | 历史编码误差 | 0.016–0.064 | 0.018–0.061 | 0.035–0.085 |
| **动作响应** | 阶跃后 1–2 步 | 见 §4.4 | — | — |
| **长期漂移**（后 10%） | 累积误差 | 0.038–0.110 | 0.025–0.041 | 0.024–0.063 |

**结论**：
- GRU 初始偏差小，但漂移快
- RSSM/PC-LWM 初始偏差大，但更稳定
- **对 MPC（短时预测）而言，GRU 占优**

## 八、明确建议

### 8.1 是否进入 III-B（数据补充）？

**⚠️ 建议先做小规模补充（5–10 条），再进 III-C。**

理由：
- GRU 已可用（test_ctrl 0.034），**不补充也能进 MPC**
- 但 V4 的失效模式说明模型对"小幅 PLA 阶跃"理解不足
- 补充成本低（~2 分钟仿真）

**若时间紧张，可跳过 III-B 直接进 III-C**（用 GRU 做代理）。

### 8.2 是否进入 III-C（最小 MPC）？

**✅ 建议进入，但用 GRU 作为主代理模型。**

理由：
- GRU 在所有控制相关指标上最优
- 推理延迟 8.4 ms，MPC 可评估 12 个候选
- PC-LWM 在控制任务上无优势，不应作为首选

**MPC 设计建议**：
| 项 | 值 |
|---|---|
| 代理模型 | **GRU-h128** |
| horizon | 32（3.36 s）|
| 候选数 | ≤ 12（受 105 ms 预算限制）|
| 优化器 | CEM 或 random shooting |
| 对照 | C0（原 EEC）作为基线 |

### 8.3 对 PC-LWM 的诚实评价

> **PC-LWM 的物理锚定在"跨工况预测"（test_ood 1-step）上有优势，
> 但在"控制导向预测"（test_ctrl）上未超过 GRU。**
>
> **这不否定 PC-RSSM 5 种子实验的结论**（那里 E3 在 60s 连续推演上 +3.76%），
> **但说明该优势不能直接迁移到控制任务。**
