## 一、修复的核心问题：GRU 训练/推理不一致

### 1.1 问题（用户指正）

v2 的 `MaskGRU` 有三处不一致：

| 路径 | 输入 | 状态更新 | Decoder 输入 |
|---|---|---|---|
| 训练 `forward` | `[obs, mask, act]` → `inp` | `gru` 编码 → **`cell` 递推** | `h`（cell 输出）|
| 在线 `step`（v2）| `[obs_m, mask, act]` → `inp` | **`gru` 递推** | `out`（gru 输出）|
| 一致性 | ✅ | ❌ **不同参数** | ❌ **分布不同** |

**根因**：`self.gru` 的 `out` 是"当前步特征"，`self.cell` 的 `h` 是"递推状态"。训练时 Decoder 只见过后者。

### 1.2 v3 修复：统一状态更新原语

```python
def enc_hist(self, obs, mask, act):
    """历史编码（只在开头跑一次）"""
    x = self.inp(torch.cat([obs, mask, act], -1))
    _, hn = self.gru(x)
    return hn[-1]

def update(self, h, obs_prev, mask_prev, act_prev):
    """★ 唯一的状态更新原语（训练/在线/开环共用）"""
    o_m = apply_mask(obs_prev, mask_prev)
    z = self.cell_in(torch.cat([o_m, mask_prev, act_prev], -1))
    h_new = self.cell(z, h)
    return self.dec(h_new), h_new
```

**三条路径全部调用 `update`**：
- `forward()` — 训练
- `online_step()` — 逐步在线
- `rollout_open()` — 严格开环

## 二、三种推理模式的严格定义

| 模式 | 观测使用频率 | 定义 |
|---|---|---|
| **open_loop** | **0**（完全不用）| 故障时初始化，之后只给控制输入 |
| **segmented** | 每 32 步（3.36 s）| 用真实历史（含其他传感器）重编码 |
| **stepwise** | 每 0.105 s | 每步用正常传感器更新 |

**共同点**：相同故障前 32 步真实历史初始化、相同控制输入、相同故障时刻与评价区间。

**重要纠正**：`segmented` **不是**纯外推（它每 32 步注入真实观测）。真正的纯外推是 `open_loop`。

## 四、★ 逐通道移除实验（决定性证据）

**永久失效 @20s，逐步在线，test_id，°R：**

| 模型 | 基线 | −Wfact | −N2int | −T45 | −P36 |
|---|---|---|---|---|---|
| **MaskGRU** | 33.13 | 27.41 (**−17%**) | 23.41 (**−29%**) | 27.11 (**−18%**) | 27.47 (**−17%**) |
| **MaskRSSM** | **22.39** | 24.42 (+9%) | 21.35 (−5%) | **38.94 (+74%)** | 22.77 (+2%) |

### 判读

**MaskGRU**：移除任何传感器都**改善** 17–29%
→ **它被无关传感器信息误导**

**MaskRSSM**：移除 T45 **恶化 74%**，其他通道影响小
→ **它真正依赖 T45**（物理上 T45 是 T4 下游，最相关）

### 推翻之前的错误结论

**我之前用"输入扰动后的输出变化幅度"判定 RSSM 更善于利用其他传感器（敏感度 1.2–2.0 倍）。**

**这是错误的方法**：
- 敏感度 ≠ 有效贡献
- MaskRSSM 敏感度高，是因为它对输入变化响应强（包括噪声）
- **只有逐通道移除才能区分"利用了"和"被干扰了"**

**用户指正完全正确。**

## 七、结论

### ✅ 已验证的实验事实

1. GRU 训练/推理不一致已修复（max diff = 0.00e+00）
2. 严格开环明显差于有反馈方案
3. **MaskRSSM 在逐步在线下全面优于 MaskGRU**（8/8 组合中的 8 个，32%）
4. **MaskGRU 在分段反馈下优于 MaskRSSM**（永久失效 29.88 vs 37.17）
5. **MaskGRU 被无关传感器误导**（移除后改善 17–29%）
6. **MaskRSSM 真正依赖 T45**（移除后恶化 74%）
7. RSSM 多种子 std = 0.43（1.9%）
8. 传感器噪声对两者影响都小

### ❌ 推翻的错误结论

| 错误结论 | 正确结论 |
|---|---|
| "RSSM 更善于利用其他传感器（敏感度 1.2-2.0x）" | 敏感度是错误指标；需逐通道移除 |
| "Mask-GRU 全面优于 Mask-RSSM"（v2）| 取决于推理模式 |
| "逐步在线总是更好" | 取决于模型：GRU 分段更好，RSSM 逐步更好 |

### ⚠️ 不能得出的结论

1. **不能说"RSSM 全面优于 GRU"** —— 分段反馈下 GRU 更好
2. **不能把单种子训练结果当统计显著** —— 但推理多种子显示稳定
3. **不能忽略 test_ood 的异常**（缺失 5s/10s GRU 开环 5.25/7.95）—— 需核查

### 待验证

1. test_ood 缺失 5s/10s 的开环异常低值（5.25/7.95）—— 可能该轨迹 T4 变化小
2. 为什么 RSSM 分段反馈差但逐步好
3. 训练种子敏感性（当前只有 seed=0）
